## DL-2026-09-23-01 — Change a UI stack by registration and attrition, not a rewrite

**Areas:** Software engineering; Product and design

**Tags:** `frontend`, `migration`, `technical-debt`

### What I learned

A new component library can be adopted without a big-bang rewrite: new surfaces use the new stack, old files that still use the legacy library are listed in a register that may only shrink, and a check enforces it.

### What I did

I recorded the move to a React, Tailwind, Radix and shadcn stack for new surfaces, with the previous library kept only on registered files and retired as those surfaces are rebuilt for other reasons.

### Evidence or example

The rule also requires that a converted surface keeps every API call and runtime binding, after an earlier restyle had silently disconnected a working route.

### Why it matters

Rewrites stall feature work and reintroduce bugs. A shrinking register makes progress visible and prevents new debt.

### Open questions

- When does the remaining register become small enough to finish deliberately?

### Next step

Check the legacy register in continuous integration so it can never grow.
